## Part 1. Per-product findings

### 1. Intercom Fin

**Actions ("Data connectors"; formerly "Custom Actions"/"Fin Actions")**

- Intercom renamed Custom Actions to **Data connectors**; old "custom action" URLs redirect. https://www.intercom.com/help/en/articles/6298282-how-to-set-up-data-connectors-for-workflows-and-inbox
- Definition is **form-based, not OpenAPI**: name, internal description, HTTPS URL, method (GET/POST/PUT/DELETE/PATCH), auth, custom headers, and typed **inputs** (Text/Number/Decimal/Boolean) whose source is "Let Fin collect", a People attribute, or a custom value; dynamic values are inserted with an **Attribute Inserter** picker. https://www.intercom.com/help/en/articles/9916497-how-to-set-up-data-connectors
- **Response handling**: "Test connection" returns the raw response; optional Table view / Python transform / mapping to contact attributes; draft/live versioning with rollback; 15 s timeout (30 s inside Procedures). Same URL.
- For Fin specifically **no response mapping is required**: "Fin directly interprets the JSON response"; XML auto-converts; "Test request" button. https://www.intercom.com/help/en/articles/6298282-how-to-set-up-data-connectors-for-workflows-and-inbox
- **How Fin decides to call it**: "Enabled (direct trigger)" = "Fin triggers the connector automatically based on the customer's question — no workflow required"; "Disabled" = only when placed in a Workflow/Procedure/Macro. Audience gating per connector. https://www.intercom.com/help/en/articles/9916497-how-to-set-up-data-connectors
- Selection is driven by the connector's natural-language **description** (3–5 specific sentences with example queries). https://www.intercom.com/help/en/articles/9916183-best-practices-when-using-data-connectors-with-fin
- API-design guidance: connectors handle JSON nested 1–2 levels; nested object/array *inputs* not supported; design endpoints **idempotent** ("Fin may submit the same refund request multiple times"); 429/500 → retry, 410 → stop. https://www.intercom.com/help/en/articles/10576235-designing-and-using-your-apis-with-data-connectors
- **Auth types**: pre-configured 3-legged OAuth (Salesforce, HubSpot, Attio); Text tokens (static header); HTTP Request tokens (auto-refresh); OAuth Request tokens (client credentials); User tokens (per-user e.g. JWT). Auto-refresh on 400/401/403. https://www.intercom.com/help/en/articles/6615543-setting-up-data-connectors-authentication
- Requests originate from Intercom's backend; config encrypted at rest; available on all plans. https://www.intercom.com/help/en/articles/9916507-fin-and-data-connectors-faqs
- **Templates**: Shopify Storefront (product search, cart, policies), Statuspage, Stripe (read-only). https://www.intercom.com/help/en/articles/9909996-use-data-connector-templates
- **Limit**: "Fin can only process one connector call per turn." https://www.intercom.com/help/en/articles/11461635-add-mcp-connectors-for-popular-apps-or-custom-mcps
- Pricing: "Actions don't add charges"; $0.99 per outcome (Resolution / Procedure handoff / Disqualification), Qualification $9.99. https://www.intercom.com/help/en/articles/8205718-fin-ai-agent-outcomes

**Identity gating of connectors ("Customer authentication")**

- Per-connector **Security tab → "Customer authentication"** toggle "enforces your workspace's authentication rules before the connector can access or display sensitive information". https://www.intercom.com/help/en/articles/9916497-how-to-set-up-data-connectors
- Workspace rules (Settings > Workspace > Security > Customer authentication): per channel and audience; two methods — **Email OTP** and **Messenger security (JWT)** ("strongest identity guarantee"). https://www.intercom.com/help/en/articles/6615543-setting-up-data-connectors-authentication
- OTP mechanics: 6-digit code, 10 min validity, 3 attempts, 30-min reuse window across connectors. https://www.intercom.com/help/en/articles/10741459-secure-data-connectors-with-one-time-passcode
- Standalone Workflow step "Verify email with OTP". https://www.intercom.com/help/en/articles/13406768-verifying-customer-identity-with-email-otp-workflow-step

**Fin Tasks → Fin Procedures**

- **Fin Tasks**: natural-language multi-step instructions combining connectors; new Task creation **disabled from March 12, 2026**. https://www.intercom.com/help/en/articles/9569407-fin-tasks-explained
- **Fin Procedures** (current, GA): "AI-driven, natural language instruction document"; sections for when to trigger, steps, escalation; if/else; embedded code blocks; connectors invoked with `@` → "Call data connector"; sub-procedures; sequential execution; auto-escalation. https://www.intercom.com/help/en/articles/12495167-fin-procedures-explained ; https://www.intercom.com/help/en/articles/13459820-how-to-use-data-connectors-in-fin-procedures
- Testing = **Simulations** (AI plays the customer; pass/fail; saved as regression tests). https://www.intercom.com/help/en/articles/13617008-fin-procedures-faqs
- Comparison of Procedures vs Tasks vs Workflows. https://www.intercom.com/help/en/articles/14077835-procedures-vs-tasks-vs-workflows
- No human-approval step for actions is documented; guardrails = audience rules, customer authentication, sequential execution, auto-escalation, Fin AI Engine safety checks. https://www.intercom.com/help/en/articles/7120684-fin-ai-agent-explained

**Fin as an MCP client ("MCP connectors")**

- Announced May 1, 2025: Fin acts as an MCP client; MCP tools appear as Data connectors. https://www.intercom.com/blog/introducing-model-context-protocol-fin/
- Templates for **Linear, Stripe, Shopify, Zapier**; **"Custom MCP"** = any MCP-compliant server via base URL + OAuth 2.0 or token; per-tool About/Input parameters/Test response/Data access. https://www.intercom.com/help/en/articles/11461635-add-mcp-connectors-for-popular-apps-or-custom-mcps

**Content sources**

- Native: Help Center, Snippets, Internal articles, Website sync, PDF upload. External: **Zendesk, Guru, Notion, Confluence** (import or sync), **Salesforce Knowledge, Box, Freshdesk, Document360** (sync only). Google Drive / SharePoint not listed. https://www.intercom.com/help/en/articles/7837514-add-your-content-for-fin-ai-agent ; https://www.intercom.com/help/en/articles/9454619-sync-or-import-internal-articles-from-external-sources
- Spreadsheets: community answer suggests a public URL as a website source, or snippets/PDF for internal data; no native sheet source. https://community.intercom.com/fin-faqs-97/can-i-feed-a-excel-sheet-to-fin-9074

**Identity verification (Messenger)**

- Legacy `user_hash` = HMAC-SHA256 of user_id/email; **deprecated**. https://www.intercom.com/help/en/articles/7946878-what-is-identity-verification-deprecated
- **JWT** (`intercom_user_jwt`, HS256): `user_id` required; optional `email`, `exp`, custom attributes; fresh JWT per boot; "Enforce Messenger Security"; "Any attribute that you want Fin to use in a critical part of an Action or Workflow should be protected." https://www.intercom.com/help/en/articles/10589769-authenticating-users-in-the-messenger-with-json-web-tokens-jwts ; https://developers.intercom.com/installing-intercom/web/identity-verification ; changelog https://www.intercom.com/changes/en/91608-a-new-secure-way-to-authenticate-messenger-users-with-jwts
- "Require verified updates" setting ignores unsigned Messenger attribute writes. https://www.intercom.com/help/en/articles/11087109-securing-the-data-you-send-via-the-messenger
- With identity verification, Fin auto-accesses name, email, city, country, locale and Custom Data Attributes. https://www.intercom.com/help/en/articles/7120684-fin-ai-agent-explained

**Attributes / events**

- Attributes (people, company, conversation, ticket, temporary) are inserted into connector URLs/bodies and read/updated in Procedures via `@`. https://www.intercom.com/help/en/articles/10546434-how-attributes-can-power-your-fin-tasks-workflows-and-data-connectors
- `window.intercomSettings` fields: user_id, email, name, created_at, user_hash, company{...}; other keys become custom attributes. https://developers.intercom.com/installing-intercom/web/attributes-objects
- No official page found stating Fin uses **events** in answer generation. [inferred absence]

**Intercom MCP server (Intercom as server) and Fin Agent API**

- `https://mcp.intercom.com/mcp` (US) / `https://mcp.eu.intercom.com/mcp` (EU); OAuth; 14 tools (search/fetch conversations, contacts, companies, articles read/write, add note). For external AI to reach Intercom data — not for Fin to reach tenant systems. https://developers.intercom.com/docs/guides/mcp
- **Fin Agent API**: `/fin/start`, `/fin/reply`, `/fin/capabilities`, `/fin/ask`, `/fin/procedures/{id}/run`, `/fin/escalate`. https://developers.intercom.com/docs/guides/fin-agent-api
- **Fin Agent API: MCP Server** (beta, Jul 2, 2026): external agents call Fin as a tool; end-user endpoint authenticated with the same HS256 JWT secret as the Messenger. https://www.intercom.com/help/en/articles/15481203-fin-agent-api-mcp-server

### 2. Zendesk AI agents (ex-Ultimate)

- Advanced capabilities (agentic reasoning, procedures, API integrations) expanded to **all** Suite/Support plans (announced Mar 30, 2026; rollout May 11–Jun 12, 2026; Essential retired Dec 10, 2026). https://support.zendesk.com/hc/en-us/articles/10487730059034-Announcing-expanded-access-to-AI-agent-capabilities-for-all-Zendesk-customers ; https://support.zendesk.com/hc/en-us/articles/6970583409690-About-AI-agents
- **Integration builder** (form): name + **description** ("extremely important" — agentic AI uses it to pick the API); typed **request parameters** referenced as `{{parameterName}}`; per-**environment** URL/method; headers; JSON body; **auth: API Key, Bearer, Basic, OAuth 2.0, AWS Signature, Custom (expiring token)**; **Test** returns statusCode/data; **Scenarios** Success/Failure/Fallback; response mapped into **session parameters** via **JSONata**. https://support.zendesk.com/hc/en-us/articles/8357756844442-About-the-integration-builder-for-advanced-AI-agents ; https://support.zendesk.com/hc/en-us/articles/8920235767834-Passing-request-parameters-in-the-integration-builder-for-advanced-AI-agents

- **Generative procedures**: free-text business policy → auto-generated **procedure map**; tied to a **use case** (intent); "Run integration" blocks collect missing params. https://support.zendesk.com/hc/en-us/articles/10473649691418-About-generative-procedures-for-AI-agents ; https://support.zendesk.com/hc/en-us/articles/8979864563610-Creating-generative-procedures-to-shape-flexible-conversation-flows-for-AI-agents

- **Knowledge**: help centers (respects restricted-article permissions by auth status), web crawler, knowledge connectors (~24 h sync). https://support.zendesk.com/hc/en-us/articles/8357749301658-Connecting-knowledge-sources-to-power-generative-replies-in-advanced-AI-agents ; import of Zendesk/Salesforce/Freshdesk help centers, Confluence, **CSV files**, crawler. https://support.zendesk.com/hc/en-us/articles/10791195957530-Importing-knowledge-sources-to-power-generative-replies-in-AI-agents-AI-agents-Advanced-only ; account-level connectors (S3, Box, Confluence, Contentful, Document360, Dropbox, Freshdesk, Google Drive, Guru, HubSpot, Jira, Notion, Salesforce, SharePoint, Universal REST). https://support.zendesk.com/hc/en-us/articles/9796599390874-Connecting-external-knowledge-sources-to-your-Zendesk-account

- Widget data: `zE("messenger:set","conversationFields",...)`, `conversationTags`. https://developer.zendesk.com/api-reference/widget-messaging/web/core/ ; https://support.zendesk.com/hc/en-us/articles/5658339908378-Using-messaging-metadata-with-the-Zendesk-Web-Widget-and-SDKs

### 3. Ada

- **Reasoning Engine**: inputs = context, knowledge, configured Actions, Playbooks; outcomes = clarify, answer, execute an Action, run a Playbook, hand off. https://docs.ada.cx/docs/welcome/agent-logic ; "Unified Reasoning Engine" release (Feb 2026). https://docs.ada.cx/release-notes/2026/2/3
- **API tools** (formerly Actions; form): Name, **Description** ("when the AI Agent should use it"), "AI Agent only uses this API tool within Processes or Playbooks" (default on), access rules by variable, **Get input from chat** inputs, Endpoint (URL with `@` token/inputs, method GET/POST/PATCH/PUT/DELETE), Headers, Body (JSON/XML/form), **Test API Response**, outputs via **JMESPath** with "Give my AI Agent access to this information" / "Save output as variable". https://docs.ada.cx/docs/automation/tools/api-tools/api-tool-control ; overview https://docs.ada.cx/docs/automation/tools/api-tools
- **No OpenAPI import documented**; Tools API manages "HTTP tools (api)" and "Code tools (code)". https://docs.ada.cx/reference/tools/overview
- **Token configuration**: Static tokens and **Customer login tokens** (OAuth: Auth URI, Token URI, Client ID/Secret, Redirect URI, scopes, PKCE). https://docs.ada.cx/docs/automation/tools/api-tools/token-configuration
- **Code tools**: sandboxed Python, ~5 s, whitelisted domains. https://docs.ada.cx/docs/automation/tools/code-tools
- **MCP tools**: "a tool that already lives on an MCP server your company runs"; add by URL + credential; tools discovered, disabled by default, enabled one at a time; 30 s timeout; can be gated in Playbooks. https://docs.ada.cx/docs/automation/tools/mcp-tools ; per-user token forwarding via "Customer token field name" (sensitive metadata, 24 h TTL). https://docs.ada.cx/docs/automation/tools/mcp-tools/authentication-and-channels
- **Ada MCP server** (Ada as server, admin-side: analytics, knowledge, Playbooks, tests). https://docs.ada.cx/reference/introduction/mcp-server
- **Guidance is legacy** → **Custom Instructions** (≤300 chars each, max 10 active). https://docs.ada.cx/docs/automation/custom-instructions
- **Playbooks**: SEND/SET/ASK/RUN/IF-ELSE/GO TO; RUN executes API tools/handoffs; Processes legacy. https://docs.ada.cx/docs/automation/playbooks ; testing https://docs.ada.cx/docs/automation/playbooks/test-and-publish
- **Knowledge integrations**: Zendesk Guide (15 min), Salesforce Knowledge, Contentful, Dixa, Gladly, ServiceNow, Helpjuice, Microsoft Dynamics; Knowledge API; web import. Confluence/Notion not listed. https://docs.ada.cx/docs/knowledge/content-ingestion/knowledge-integration
- **End-user auth**: Sign In block (OAuth; token stored as variables; "should happen before your AI Agent shares any sensitive data"). https://docs.ada.cx/docs/automation/greetings/blocks/sign-in-and-sign-out-blocks ; Embed SDK `metaFields` / `sensitiveMetaFields` (encrypted, 24 h), `zdChatterAuthCallback` JWT. https://docs.ada.cx/reference/embed2-reference ; End Users API `external_id`, `sensitive_metadata` "excluded from LLM context". https://docs.ada.cx/reference/end-users/overview ; Auth Tokens API for short-lived identity tokens. https://docs.ada.cx/reference/introduction/overview
- Webhooks (signed, 7 retries). https://docs.ada.cx/reference/webhooks/overview ; Handoffs (max five active; AI chooses by name+description). https://docs.ada.cx/docs/handoffs/handoff-management

### B. The dominant 2026 pattern for "let the AI agent call the customer's API"

Every major product converges on the same shape; none of the support-specific vendors imports OpenAPI (that remains an OpenAI GPT Actions / Salesforce External Services / Copilot Studio pattern).

1. **A form-defined action, not code and not OpenAPI**: name; a natural-language *"when to use"* description that drives tool selection; typed inputs the model may collect from the conversation or take from verified user attributes; URL + method + headers + body template with variable insertion; a credential chosen from a vault. Intercom (https://www.intercom.com/help/en/articles/9916497-how-to-set-up-data-connectors), Zendesk (https://support.zendesk.com/hc/en-us/articles/8357756844442-About-the-integration-builder-for-advanced-AI-agents), Ada (https://docs.ada.cx/docs/automation/tools/api-tools/api-tool-control), Chatbase (https://www.chatbase.co/docs/user-guides/chatbot/actions/custom-action), HubSpot (https://knowledge.hubspot.com/customer-agent/set-up-actions-for-the-customer-agent), Gorgias (https://docs.gorgias.com/en-US/create-actions-use-advanced-options-to-build-custom-actions-for-ai-agent-1060364), Voiceflow (https://www.voiceflow.com/docs/documentation/build/tools/api-tool.md), Tidio (https://help.tidio.com/hc/en-us/articles/20344365583132-Lyro-Smart-Actions).
2. **A test panel** that fires the real request (or accepts sample JSON) and shows the raw response, with a green tick and the ability to build against a mock response before the API exists (Intercom "Test response", Chatbase "Test Response", Ada "Test API Response", Zendesk "Test", Gorgias "Test Request", Voiceflow "Run").
3. **Response handling in two modes**: hand the raw JSON to the model (Intercom "Fin directly interprets the JSON response"; Chatbase with a 20 KB cap and Full/Limited data access) *and/or* map fields into variables with a path language (Zendesk JSONata → session parameters; Ada JMESPath; Gorgias JSONPath; Voiceflow object path) so deterministic flows and the LLM can both use the result.
4. **Invocation by LLM tool-calling with a dual mode**: the same action can be "direct trigger" (model decides from description) or restricted to explicit use inside a procedure/flow (Intercom Enabled/Disabled; Ada "only within Processes or Playbooks" default on; Chatbase "Only use in procedures"; Gorgias "only from inside a skill"; Voiceflow playbook vs API step).
5. **Guardrails around the call**: per-action audience rules; per-action **identity gate** (Intercom Customer authentication; Crisp "Require user identity verification"; Chatbase identified-contact requirement; Sierra Deterministic Guards); **customer confirmation before writes** (Gorgias auto-enabled for certain operations; OpenAI `x-openai-isConsequential` / `require_approval`); **conditions** on data before acting (Gorgias "Order Date is less than 2 hours ago"); idempotent write endpoints (Intercom); timeouts (Intercom 15/30 s, Ada MCP 30 s, Crisp widget tools 10 s); response size caps; one tool call per turn (Intercom); audit/event logs (Gorgias, Zendesk Used-by).
6. **Natural-language procedures layered on actions** (Intercom Procedures, Zendesk generative procedures, Chatbase Procedures, Ada Playbooks, Decagon AOPs, Sierra Journeys) with **simulation-based testing** (Intercom Simulations, Decagon Simulations, Sierra Simulations, Ada Test AI Agent).
7. **MCP as the second on-ramp** beside the form: a tenant registers a remote MCP server URL + credential, tools are auto-discovered and enabled individually, and they behave exactly like form actions at runtime (Intercom Custom MCP, Zendesk MCP connections, Ada MCP tools, Crisp Hugo MCP API, Voiceflow MCP tool).

### C. How end-user identity is handled so account data can be discussed safely

- **Server-signed identity has moved from HMAC hash to short-lived JWT.** Intercom deprecated `user_hash` for `intercom_user_jwt` (HS256, `user_id` required, `exp`, attributes inside the token are tamper-proof): https://www.intercom.com/help/en/articles/10589769-authenticating-users-in-the-messenger-with-json-web-tokens-jwts. Chatbase likewise recommends JWT and marks `user_hash` deprecated: https://www.chatbase.co/docs/developer-guides/identity-verification. Zendesk messaging is JWT-only (HS256, `external_id`, `email_verified`): https://developer.zendesk.com/documentation/conversations/messaging-platform/users/authenticating-users-your-app/. Pylon accepts both, with JWT ≤15 min: https://docs.usepylon.com/pylon-docs/chat-widget/identity-verification. Crisp and Front still use HMAC of the email: https://docs.crisp.chat/guides/chatbox-sdks/web-sdk/identity-verification/ ; https://dev.frontapp.com/docs/identify-users. The reason for JWT is expiry + carrying attributes that the page cannot edit; Intercom: "Any attribute that you want Fin to use in a critical part of an Action or Workflow should be protected."
- **"Verified vs unverified" is a gate on actions/data, not on the whole bot.** Intercom's per-connector "Customer authentication" toggle enforces workspace rules (JWT or Email OTP) "before the connector can access or display sensitive information": https://www.intercom.com/help/en/articles/9916497-how-to-set-up-data-connectors. Crisp's per-tool "Require user identity verification" sends an OTP: https://help.crisp.chat/en/article/how-to-build-mcp-integrations-with-hugo-tlrqmn/. HubSpot's "Data protection level" (Match email / Verify email) gates contact properties: https://knowledge.hubspot.com/customer-agent/allow-the-customer-agent-to-access-and-update-crm-data. Zendesk branches on the Get User authenticated state: https://support.zendesk.com/hc/en-us/articles/5314129059482-Using-authentication-metadata-in-an-AI-agent-answer-Legacy. Sierra blocks account-modification tools until authenticated: https://sierra.ai/blog/defense-in-depth-in-the-age-of-agents. Zendesk help-center restricted articles are also filtered by auth status: https://support.zendesk.com/hc/en-us/articles/8357749301658-Connecting-knowledge-sources-to-power-generative-replies-in-advanced-AI-agents.
- **Fallback for anonymous visitors is an in-chat email/SMS OTP**, universally: Intercom (6-digit, 10 min, 3 attempts, 30-min reuse: https://www.intercom.com/help/en/articles/10741459-secure-data-connectors-with-one-time-passcode), Gorgias (https://helpcenter.gorgias.com/en-US/set-up-and-use-ai-agent-on-chat-828220), Crisp, Salesforce guest users (https://help.salesforce.com/s/articleView?id=platform.ls_agentforce_guest_users.htm&language=en_US&type=5), HubSpot "Verify email". E-commerce adds order-number + ZIP/phone matching (Gorgias Trust System; Tidio email + order ID).
- **OAuth inside the chat** is the enterprise variant: Ada's Sign In block with customer login tokens (PKCE) yields a per-user access token that subsequent API tools pass through (https://docs.ada.cx/docs/automation/greetings/blocks/sign-in-and-sign-out-blocks); Ada MCP tools forward a per-user token from sensitive metadata (https://docs.ada.cx/docs/automation/tools/mcp-tools/authentication-and-channels); Shopify Customer Accounts MCP is OAuth+PKCE per shopper (https://shopify.dev/docs/apps/build/storefront-mcp/servers/customer-account); Intercom "User tokens" per-user credentials (https://www.intercom.com/help/en/articles/6615543-setting-up-data-connectors-authentication).
- **Unsigned attributes are treated as untrusted**: Intercom "Require verified updates" (https://www.intercom.com/help/en/articles/11087109-securing-the-data-you-send-via-the-messenger); Ada `sensitive_metadata` is excluded from LLM context (https://docs.ada.cx/reference/end-users/overview).

### D. Where MCP fits, and who lets a tenant plug in their own server

- **Two distinct roles.** (1) *Platform as MCP server* — lets ChatGPT/Claude/Cursor read the platform's own data: Intercom, HubSpot, Stripe, Gorgias, Crisp, Ada, Voiceflow (builder), Shopify, Atlassian, Notion, Zapier; Zendesk announced. (2) *Platform as MCP client* — the support agent consumes tools from a server the **tenant** runs. Role (2) is what matters for your question.
- **Vendors that let a tenant plug in their own MCP server today (documented):** Intercom Fin "Custom MCP" (URL + OAuth 2.0 or token; per-tool enable/inputs/test; one call per turn) https://www.intercom.com/help/en/articles/11461635-add-mcp-connectors-for-popular-apps-or-custom-mcps ; Zendesk MCP connections (OAuth-only, HTTP only, 250 tools) https://support.zendesk.com/hc/en-us/articles/10497779528730-Connecting-to-MCP-servers-and-using-MCP-tools-in-action-flows ; Ada MCP tools (tools off by default, 30 s timeout, per-user token forwarding) https://docs.ada.cx/docs/automation/tools/mcp-tools ; Crisp Hugo MCP API (Bearer/Basic + HMAC request signing + per-tool OTP) https://docs.crisp.chat/guides/hugo/mcp-api/ ; Voiceflow MCP tool (hosted only, header auth) https://www.voiceflow.com/docs/documentation/build/tools/mcp-tool.md. Marketing-only: Tidio, Decagon. HubSpot Agent Builder only allows an allow-list of eight servers. **Not supported:** Chatbase, Botpress, Gorgias AI Agent, HubSpot customer agent.
- **Common client constraints**: remote Streamable HTTP only (no stdio); auth = bearer/header or OAuth 2.0 (Zendesk insists on OAuth; the spec mandates OAuth 2.1 + PKCE + RFC 9728 for HTTP: https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization); tools disabled by default and enabled individually; tool description is the selection signal; identity gating applied per tool. The 2026-07-28 spec makes servers stateless (no session header), which simplifies hosting behind a plain load balancer: https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/.
- **UI-bearing tool results** are being standardised as "MCP Apps" (OpenAI Apps SDK implements it: https://developers.openai.com/apps-sdk/mcp-apps-in-chatgpt), which is the closest analogue to your connector SDK's "fixed shapes rendered as cards".
- **Commerce specifically**: Shopify's Storefront MCP (no auth) and Customer Accounts MCP (per-shopper OAuth) mean a Shopify tenant needs no custom code for catalog/cart/policies/order status — Intercom and Crisp both ship Shopify as an MCP template.

### E. Recommendations for your product

Your current stack: (a) vector KB (URLs/PDF/text), (b) workflow "Call an API" node with Shopify/Stripe/Zendesk/Slack/HubSpot presets, (c) a connector SDK the tenant hosts at one URL with HMAC+timestamp signing and fixed-shape methods rendered as cards, (d) HMAC identity verification, (e) a Google Sheets import that stores rows the assistant does not read.

Notable: your connector SDK is functionally the same design Crisp shipped as "Hugo MCP API" (tenant-hosted server, HMAC-signed requests with timestamp, session id header, per-tool OTP gate) — except Crisp made the wire protocol MCP so tenants can reuse any MCP server, and the platform can reuse Shopify/Stripe servers. That is the cheapest way to see where your SDK should go.

**1. (Highest value) Ship form-defined "Actions" invoked by LLM tool-calling, and make the workflow node and the action share one definition.**
- Why: it is the one feature every product in the table has, from $40/mo Chatbase to Sierra, and it is where resolution rate comes from (order status, booking, account lookups). Your "Call an API" node is only reachable from a flow, which is the pre-2024 pattern (Zendesk dialogues, Tidio Simple Actions — both now "legacy"). Intercom's own comparison shows the direction: deterministic Workflows kept for buttons/branches, Procedures + connectors for everything else (https://www.intercom.com/help/en/articles/14077835-procedures-vs-tasks-vs-workflows).
- Spec to copy: name; "when to use" description (3–5 sentences with example queries, per https://www.intercom.com/help/en/articles/9916183-best-practices-when-using-data-connectors-with-fin); typed inputs with source = collect from chat / verified user attribute / constant; URL/method/headers/body with `{{variable}}` insertion; credential from a per-tenant vault (API key/bearer/custom header now, OAuth client-credentials next, like Intercom's token types https://www.intercom.com/help/en/articles/6615543-setting-up-data-connectors-authentication); test panel with live call *and* pasted sample JSON; response mode "give raw JSON to model" with a size cap (Chatbase 20 KB) plus optional JSONPath extractions into variables the workflow node can use; mode toggle "Direct trigger" vs "Only inside a workflow"; audience rules; **"Require verified visitor"** toggle; conditions/confirmation for non-GET methods (Gorgias pattern); idempotency guidance in docs; 15–30 s timeout; one tool call per turn to start; audit log per call. Convert your five presets into **action templates** (Intercom, Chatbase, HubSpot Actions Library all do this).
- Bonus that costs little given you already render cards: a **client-side tool** registration in the widget (Chatbase `registerTools`, Crisp Widget Tools, 10 s timeout) for tenants whose data is only in the logged-in browser session.

**2. Upgrade identity to JWT with expiry, keep HMAC, and add an OTP fallback — then gate actions and KB on it.**
- Why: HMAC user hash is now deprecated at Intercom and Chatbase in favour of HS256 JWTs with `exp` and tamper-proof attributes; every vendor gates account data on a verified state; anonymous visitors get an in-chat email OTP. Without the gate, step 1 cannot safely expose order/account lookups.
- Spec: accept `token` (HS256 signed with the tenant's existing secret; `sub`/`user_id` required, `exp` ≤ 24 h recommended short, optional email/name/custom attributes) alongside the current `user_hash`; mark the session `verified` only when signed; expose `verified`, `user_id`, and signed attributes as inputs to actions; "Require verified visitor" on actions falls back to a built-in **email OTP step** (6-digit, 10 min, 3 attempts, 30-min reuse — Intercom's numbers); a workspace setting "ignore unsigned attribute updates"; per-KB-source audience rules (e.g., "logged-in customers only") like Zendesk restricted articles.

**3. Turn the connector SDK into an MCP-compatible server (and add an MCP client) rather than growing a proprietary method list.**
- Why: Intercom, Zendesk, Ada, Crisp and Voiceflow all consume tenant MCP servers; Shopify (Storefront + Customer Accounts), Stripe, HubSpot, Zapier and Notion all expose MCP servers you could offer as one-click templates instead of maintaining presets; the spec is stable under the Linux Foundation with a stateless HTTP core since 2026-07-28. Your SDK's value (typed schemas, HMAC signing, cards) survives: Crisp keeps HMAC request signing *on top of* MCP, and MCP Apps standardises UI hints on tool results.
- Spec: (a) SDK v2 = "build an MCP server in 20 lines" — same `searchProducts/getProduct/listAvailability/bookAppointment` helpers, but exposed as MCP tools over Streamable HTTP, with your HMAC+timestamp signature added as headers (`X-<You>-Timestamp`, `X-<You>-Signature`, `X-<You>-Session-Id`, Crisp-style) and a `_meta` hint that tells your widget which card to render; (b) platform side, an "Add MCP server" form (URL, None/Bearer/Basic/custom header now, OAuth 2.0 later), tool discovery, per-tool enable + "when to use" override + "require verified visitor", 30 s timeout; (c) templates for Shopify Storefront MCP (no auth needed), Shopify Customer Accounts MCP (per-shopper OAuth, gives order status without your own code), Stripe MCP (read-only), Zapier MCP for the long tail.
- Order: 1 → 2 → 3. Step 3 reuses step 1's runtime (an MCP tool is just an action whose definition was discovered rather than typed).

**What to do with the Google Sheets import — do both, in this order.**

- *Now (cheap, unblocks the stored rows):* index each row into the existing vector store as one chunk, serialised as `Header: value` pairs, with the sheet id and each column stored as chunk **metadata** so retrieval can filter (e.g. `locale = US`). This is exactly how Voiceflow treats CSV/XLSX ("each row as a separate chunk", headers become field names, metadata filtering static or dynamic): https://www.voiceflow.com/docs/documentation/build/Importing-data-sources.md ; https://www.voiceflow.com/docs/changelog/knowledge-base-tabular-data-metadata-and-query-filtering.md. Peers offering tabular knowledge the same way: Crisp CSV Q&A (https://help.crisp.chat/en/article/how-to-train-hugo-ai-agent-on-your-data-ijkdrl/), Chatbase Q&A bulk import 100 rows (https://www.chatbase.co/docs/user-guides/chatbot/data-sources), Zendesk CSV knowledge import (https://support.zendesk.com/hc/en-us/articles/10791195957530-Importing-knowledge-sources-to-power-generative-replies-in-AI-agents-AI-agents-Advanced-only), HubSpot CSV/XLS files and "Short Answers" (https://knowledge.hubspot.com/customer-agent/manage-the-customer-agents-content-sources), Tidio CSV. Add a refresh schedule (daily/weekly, as Voiceflow and Zendesk do) so a sheet is a living source. This handles FAQ tables, pricing tables, store lists, policy matrices — the typical "small business keeps it in a sheet" case — with zero new UI beyond a "sync" toggle.
- *Next (once Actions exist):* expose the same stored rows as a **built-in structured lookup action** — "Look up in sheet <name> where <key column> = <value>" — with the tenant designating key/searchable columns and the model calling it by tool-calling. This is Botpress Tables' "Find Records" with "Searchable" columns (https://botpress.com/docs/studio/concepts/tables/) and Voiceflow's Google Sheets "Get rows" tool (https://www.voiceflow.com/docs/docs/google-sheets.md). It answers exact-match questions vector search gets wrong ("what is the status of ticket 4821", "is SKU X in stock") and returns rows you can render as cards. Rule: if a sheet has a customer-identifying key column (email, order id), the lookup should be limited to the **verified** visitor's own key (from step 2) — this is the same reasoning behind Intercom's per-connector authentication and HubSpot's "Match email".
- Do not build write-back (append/update rows) until a tenant asks; no support product in the table lets the *customer-facing* agent write to a sheet except Voiceflow/Botpress, which are general bot builders.

**Lower-priority items seen in the market that you can defer:** natural-language "procedures" with simulations (Intercom/Zendesk/Chatbase/Decagon) — valuable but only after actions exist; helpdesk knowledge connectors (Notion, Confluence, Zendesk) — a URL crawl covers most SMB cases; resolution-based pricing — an industry norm now ($0.50–$0.99 per resolution) worth noting for packaging, not engineering.
